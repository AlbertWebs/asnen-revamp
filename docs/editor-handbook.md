# Editor Handbook — ASNEN CMS

Plain-language guide for staff who edit the ASNEN website.

## Logging in

1. Go to **https://your-site.org/login** (not `/register` — public registration is disabled).
2. Sign in with the email and password provided by your administrator.
3. After login you are taken to the **Admin dashboard** at `/admin`.

If you forget your password, use **Forgot password** on the login page.

## Editing pages and blocks

1. Open **Pages** in the admin sidebar.
2. Select a page or create a new one.
3. Edit the title, excerpt, and content blocks.
4. **Save** your changes — saving does **not** make content public.

### Page blocks

Home and landing pages use **blocks** (hero, metrics, featured story, etc.). Each block has:

- **Type** — what kind of content it displays
- **Visibility** — hidden blocks are not shown on the public site
- **Content** — text, links, and settings for that block

Always preview how blocks read together before publishing.

## Publish workflow

Content moves through these states:

| Status | Meaning |
|--------|---------|
| **Draft** | Work in progress; not visible publicly |
| **In review** | Ready for an editor or admin to check |
| **Approved** | Cleared internally but not yet live |
| **Scheduled** | Will go live at a set date/time |
| **Published** | Live on the website |
| **Archived** | Removed from public view but kept in CMS |

**Authors** can create and edit drafts but usually **cannot publish**. Editors and administrators can publish.

To publish a page: open it in admin → click **Publish**. To remove from the site: **Unpublish**.

## Media and consent

Before uploading photos or videos of children, caregivers, or identifiable persons:

1. Obtain **written consent** where required.
2. Upload through **Media** in admin.
3. Set consent status appropriately.
4. Add descriptive **alt text** for accessibility.

Do not publish gallery items or stories with identifiable imagery until consent is recorded and, where required, safeguarding is approved.

## Safeguarding

Stories, testimonials, and some media involving vulnerable persons require **safeguarding review**:

- Mark content that needs safeguarding when creating it.
- A **Safeguarding Reviewer** must approve before publish.
- If publish is blocked with “Safeguarding approval required,” contact your safeguarding lead.

Never bypass safeguarding by editing status fields directly in the database.

## Impact statistics — never invent numbers

- Only publish metrics with a **verified source** (report, audit, signed-off figure).
- Legacy or unverified stats remain **draft** until verified.
- Use **public label** for how numbers appear on the site (e.g. “700+” instead of raw counts when appropriate).
- Record **source label** and **as of date** for every metric.

If you are unsure whether a number is accurate, leave it as draft and ask the program or finance team.

## Verification status

Content and settings can have verification status:

| Status | Meaning |
|--------|---------|
| **Unverified** | Not yet checked |
| **Needs verification** | Imported or edited; must be confirmed before public display |
| **Verified** | Approved for public use |

Contact details, partner logos, team bios, and impact figures should be **verified** before they appear on key public pages. Some content (e.g. unverified partners) stays hidden even if accidentally marked published.

## Forms and submissions

Contact and membership forms create **submissions** in admin. Do not share submission data outside approved processes. Old submissions may be anonymized automatically per retention policy.

## Getting help

- Technical issues: contact your site administrator.
- Content accuracy: program leads or communications team.
- Safeguarding: designated Safeguarding Reviewer role holder.
